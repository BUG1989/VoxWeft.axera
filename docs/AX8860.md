# VoxWeft AX8860 backend

This branch keeps VoxWeft's real-time segmenter, orchestrator, interruption
logic, WebSocket protocol, and UI vocabulary, but replaces the Apple MLX model
layer with remote AX8860 llama-server endpoints.

```text
Browser ──WebSocket── VoxWeft Linux runtime
                         ├─ Qwen3-ASR   /v1/chat/completions
                         ├─ HY-MT2      /v1/chat/completions
                         └─ VoxCPM2     /v1/audio/speech
```

## Runtime dependencies

The upstream `pyproject.toml` intentionally installs Apple MLX. Linux uses a
separate environment:

```bash
python3.10 -m venv .venv-ax
.venv-ax/bin/pip install -r requirements-ax.txt
```

## Configure endpoints

Create a private `.env.ax.local` file. It is ignored by Git.

```bash
cat > .env.ax.local <<'ENV'
AX_BOARD_HOST=<board-ip>
AX_ASR_BASE=http://<board-ip>:18081/v1
AX_MT_BASE=http://<board-ip>:18082/v1
AX_TTS_BASE=http://<board-ip>:18083/v1
AX_STATS_URL=http://<board-ip>:8080/api/stats
ENV
chmod 600 .env.ax.local
```

The three expected services are:

| service | default port |
|---|---:|
| Qwen3-ASR | 18081 |
| HY-MT2 | 18082 |
| VoxCPM2 | 18083 |

Start them with your preferred board-side service manager. They must expose
OpenAI-compatible endpoints and remain reachable from the Linux runtime.

## Start the Linux runtime

`scripts/run_ax8860.sh` loads `.env.ax.local` automatically:

```bash
scripts/run_ax8860.sh
```

Open:

```text
http://127.0.0.1:3100/
```

The browser permits microphone capture only on `localhost` or HTTPS. On a
remote HTTP host, use the text box or the built-in mic-free demo.

The WebUI can also import a local audio file. The browser decodes it to mono
16 kHz PCM and sends it through the same WebSocket segmentation path, so the
feature works without microphone permissions.

For a LAN HTTPS demo, `scripts/https_proxy.js` can terminate TLS and proxy both
HTTP and WebSocket traffic to the local runtime. Generate a certificate with the
runtime host IP in `subjectAltName`, then run the proxy on a high port such as
3443. See the README for the exact commands.

## Current scope

- Interpreter mode is supported.
- Supported translation languages: `zh/en/ja/ko/fr/de/ru/es`.
- The runtime is single-session.
- Each llama-server runs with one slot (`-np 1`).
- TTS supports either the VoxCPM2 preset voice or bundled VoxWeft reference
  voices. Missing reference voices fall back to the preset.
  Reference audio is cached locally as 16 kHz PCM to keep request payloads and
  board allocator growth low; the preset voice remains the default for long
  unattended runs.
- `/health` returns model readiness, model metadata, available voices, and one
  board resource snapshot.
- The WebUI polls `/health` every five seconds. Offline stages are shown with
  their configured ports, and actions that require those stages are disabled
  until the service returns.
- Chat-completion requests retry connection errors, timeouts, HTTP 5xx, and
  malformed JSON. HTTP 4xx is not retried. TTS retries only before the audio
  stream starts.
- Long text is split into sentence-sized TTS chunks. If a chunk fails before
  audio is emitted, it is retried. If it fails mid-stream, the client can send
  `resume_speech` to continue from the next chunk without replaying audio.

## Resource monitoring

Sample the board resource endpoint and summarize the CSV:

```bash
AX_STATS_URL=http://<board-ip>:8080/api/stats \
  .venv-ax/bin/python scripts/monitor_ax_resources.py \
  --output /tmp/ax-resources.csv --interval 2

.venv-ax/bin/python scripts/ax_resource_report.py /tmp/ax-resources.csv --markdown
```

The report shows first/last/min/max values and the drift between the first and
last ten samples. Judge memory behaviour after a warm-up period and prefer a
long-running monotonic trend over a single request peak.

## Notes

- HY-MT2 should be launched with `--no-cache-prompt`. Repeating an identical
  prompt without this option can return an empty completion on the current AX
  build.
- The Linux adapter also retries an empty translation once with a unique
  request ID for compatibility with older board-side launch scripts.
- Retry counts are controlled by `AX_HTTP_RETRY_LIMIT`,
  `AX_HTTP_RETRY_DELAY`, and `VOXWEFT_SPEECH_RETRY_LIMIT`. The limits are
  additional retries after the first request.
- The WebUI does not resend an unchanged `session_config`; rebuilding the
  orchestrator used to interrupt still-playing TTS.
